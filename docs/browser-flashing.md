# Browser firmware installation

Open [AirBridge Web](https://w0x7ce.eu/AirBridge/) directly in current desktop Chrome or Edge over HTTPS. The firmware installer is part of the real application, outside the simulated demo. No Python, local service or desktop installation is required by the user. Tauri remains available separately.

## Supported hardware

The bundled **v0.0.1 full AirBridge** profile requires an **ESP32-S3, at least 16 MiB SPI Flash and 8 MiB octal PSRAM**, with the board's native USB Serial/JTAG interface accessible. N16R8 modules in different board shapes can share this image when wiring and power are compatible. A board merely containing an ESP32-S3 is not sufficient: smaller flash, no PSRAM, quad PSRAM, custom USB wiring or manufacturer security configuration may need a different firmware build. This release does not claim universal ESP32-S3 compatibility and does not control a board-specific display, LED, battery or other product peripherals.

The installer identifies the chip and reads SPI flash capacity before any flash write. Known incompatible embedded PSRAM is rejected. The ROM's feature report does not prove external PSRAM capacity or wiring; the user must explicitly confirm the N16R8 memory/native USB requirements before installation. Secure Boot, secure download and nonzero encryption configuration are rejected; no eFuses or security settings are changed.

Programming supports native USB or a compatible USB–UART adapter. **Running v0.0.1 AirBridge uses native USB**, not that UART bridge: use the socket wired to GPIO19/20, normally VID:PID **303A:1001**. A product exposing only UART needs an adapted runtime build; the browser cannot change its hardware wiring.

## Install and connect

1. Disconnect the bridge in AirBridge and close other serial tools, including Tauri. Use a spare compatible board; this replaces its application and partition table.
2. Click **Install bridge firmware → Check firmware**. The three same-origin release files are downloaded and checked against pinned SHA-256 values. No port is enumerated, opened or selected at this step.
3. Click **Choose serial port** and explicitly choose the intended board. Identification resets it into download mode and uploads Espressif's RAM flasher stub; flash is still unchanged.
4. Review the detected chip/flash, confirm memory and wiring, then click **Install & verify**. Keep the tab open, computer awake and cable connected. Progress covers writes and readback verification separately.
5. Success requires all flash MD5 checks, reset and confirmed serial release. Click **Connect to AirBridge**, choose a receive folder if needed, then explicitly choose the native USB port again. Re-enumeration may change the port name. An installed image is not yet proof of PSRAM boot, radio stability or native Apple interoperability.
6. Enable Wi-Fi/Bluetooth and AirDrop on the Apple device. Select the observed peer in AirBridge, resolve its name, and allow the intended sender before receiving. Existing transfer limits and persisted-file SHA-256 checks still apply.

## Provenance and partition preservation

The browser's immutable images match [published v0.0.1](https://github.com/tianrking/AirBridge/releases/tag/v0.0.1), source **704bfd2c4498b8411555f4232c604a4bf12cec53**. The release ZIP SHA-256 is `be0a63ca858d03b2a6c6155a4ca8e9d5790fc4c088dd5ca66c7745438554aeef`. `desktop/src/web/firmware-release.json` records each image's exact bytes, SHA-256 and offset. `desktop/scripts/verify-firmware.mjs` verifies the vendored release bytes before every build/development start; Pages preparation independently verifies every published segment and rejects missing, corrupt or unexpected files. The web installer deliberately stays on this pinned release even as the main branch changes; changing the website does not silently replace its firmware.

| Image | Offset | Bytes |
| --- | --- | ---: |
| bootloader.bin | 0x0 | 21,104 |
| partition-table.bin | 0x8000 | 3,072 |
| airbridge_native.bin | 0x10000 | 1,002,448 |

Only these segments are written, without whole-chip erase. Their erased sectors do not intersect NVS (`0x9000–0xefff`). **Do not use the merged image at offset 0 to preserve NVS:** its padding spans those sectors. The original immutable v0.0.1 ZIP's `flash.py` uses the merged image; prefer this browser installer, or explicitly write the three raw segments with esptool. The current source helper has been corrected for future packages; the published tag and archive have not been replaced. Preserving NVS is not a guarantee that data from unrelated prior applications is compatible. Per-board identity is generated by firmware, not supplied by the website.

## Interrupted or failed installation

- A cancelled chooser or incompatible chip/memory never reaches a flash write. Cancelling after inspection releases the port; the board can remain in download mode until RESET.
- During writing, cancellation waits for the current command/acknowledgement boundary or its timeout before cleanup. No new command is started after cancellation is observed. A partial image must be reinstalled. There is no automatic resend, erase-all or background flashing.
- Close other port users. Hold **BOOT**, tap **RESET**, then release BOOT. Choose the download-mode port and repeat installation. On boards without buttons, follow that board manufacturer's documented download-mode procedure; arbitrary product pinouts cannot be inferred safely.
- A readback mismatch is a failure, not success. A verified image with failed reset is reported separately; manually press RESET.
- An unconfirmed port close blocks host reconnect and further installation. Retry release; if still blocked, close the tab, unplug/replug and reopen the site. Never try to start a second application against an uncertain owner.
- HTTPS, top-level browsing and Web Serial permission are required. Enterprise browser policies can block access. Firmware installation alone does not require folder permission; file transfers do. Safari, Firefox and mobile browsers are outside this supported workflow.

## Implementation and test boundaries

The adapter uses official [Espressif esptool-js](https://github.com/espressif/esptool-js) **0.7.0** (Apache-2.0) and js-md5 **0.9.2** (MIT). They run locally in the browser and are loaded only after explicit port choice; no CDN script, firmware upload server or account is required. Flash options retain the signed-off image headers and require per-segment SPI-flash MD5 checks. A second explicit readback MD5 pass must also succeed before reset/release.

Vitest covers pinned bytes, erased-sector boundaries, explicit consent, wrong chip/memory, protection flags, download corruption, readback/reset failure, deferred cancellation and exclusive ownership through failed/timed-out cleanup. Playwright covers the actual production download/chooser path and a separate, development-only virtual device fixture for successful/error/retry interactions in all five languages, RTL and both themes. Test fixtures are not production build entrypoints. CI/Pages failure gates remain mandatory. These are automated transport/interaction checks, **not a physical ROM flash, radio or AirDrop acceptance result**. A real-board browser install, first boot and SHA-256-matched Apple roundtrip remain required hardware acceptance.
